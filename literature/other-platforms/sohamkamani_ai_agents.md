<p>AI agents are incredibly smart. They can write code, explain concepts, debug issues. But here’s the thing — they’re also incredibly generic. They don’t know your specific coding standards. They don’t know your deployment checklist. They don’t know your project structure.</p>
<div style="position:relative;padding-bottom:56.25%;height:0;overflow:hidden;clear:both;"> <iframe src="https://www.youtube.com/embed/WvBv6ASCt5E" style="position:absolute;top:0;left:0;width:100%;height:100%;border:0" allowfullscreen title="YouTube Video"></iframe> </div>
<p>That’s where <strong>AI Agent Skills</strong> come in. Based on the <a href="https://agentskills.io/specification">Agent Skills Specification</a>, skills let you package instructions, tools, and context into reusable modules that you can invoke anytime.</p>
<p>Now, here’s where it gets interesting. Different agents use different conventions for where they look for skills. OpenAI Codex uses <code>.agents/skills/</code>. Claude Code uses <code>.claude/skills/</code>. GitHub Copilot uses <code>.github/skills/</code>. And OpenCode uses <code>.opencode/skills/</code>.</p>

<h2 id="what-is-a-skill">What is a Skill?<a aria-hidden="true" tabindex="-1" href="#what-is-a-skill"><span class="anchor-link"> #</span></a></h2>
<p>Even the most capable AI agent has a gap: it doesn’t automatically know your team’s specific conventions, workflows, and preferences. Every time you need it to follow your coding standards or run your deployment process, you have to repeat the same instructions. Skills solve this by letting you package and reuse these instructions so the agent gets the right context automatically.</p>
<p><img src="/_astro/skill-folder-structure.CnKeyf_E_Z1GwY6C.webp" alt="Skill Folder Structure" loading="lazy" decoding="async" fetchpriority="auto" width="2048" height="2048"></p>
<p>A skill is simply a directory that contains a logic file called <code>SKILL.md</code> and supporting context like scripts, references, and assets.</p>
<p>The Agent Skills Specification defines a universal format that multiple AI agents support. When you invoke a skill, the contents of <code>SKILL.md</code> and any referenced files get injected into the Agent’s context window. It’s like giving the AI a cheat sheet for a specific task.</p>

<p>Now, there’s a critical distinction here that trips up a lot of people. And I want to make this crystal clear because there’s a common myth floating around.</p>
<p>Skills do not “install” software. Let me say that again — skills do not install software.</p>
<p>Here’s what’s actually happening. Your AI agent already has system tools. It can run bash commands, read files, search through code. A Skill simply orchestrates these existing tools. The <code>allowed-tools</code> list in the YAML frontmatter isn’t about installing new capabilities — it’s a permission gate. It tells the agent, “Hey, when you’re running this skill, only use these specific tools. Don’t go reading files that aren’t relevant to the task.”</p>
<p>Think of it like a bouncer at a club. The skill doesn’t create new tools — it just restricts which ones the agent can use while performing that specific task.</p>

<p>The architecture is elegant. You place your skill folders in the agent’s designated directory — that’s the auto-discovery part. And then when you invoke the skill, the contents get injected into the context. It’s that simple.</p>

<p>We’re going to build a skill for OpenAI Codex that analyzes git commits and generates a formatted standup update.</p>
<p>First, let’s create the directory structure. For OpenAI Codex, we use <code>.agents/skills/</code>. For this skill, we’ll call it “weekly-standup” and create subdirectories for scripts and references.</p>
<pre class="astro-code github-dark" style="background-color:#24292e;color:#e1e4e8;overflow-x:auto" tabindex="0" data-language="bash"><code><span class="line"><span style="color:#B392F0">mkdir</span><span style="color:#79B8FF"> -p</span><span style="color:#9ECBFF"> .agents/skills/weekly-standup/{scripts,references}</span></span>
<span class="line"><span style="color:#B392F0">touch</span><span style="color:#9ECBFF"> .agents/skills/weekly-standup/SKILL.md</span></span></code></pre>
<p>So we’ve created:</p>
<ul>
<li><code>.agents/skills/weekly-standup/</code> — the main skill folder</li>
<li><code>scripts/</code> — where we’ll put our helper scripts</li>
<li><code>references/</code> — where we’ll put templates and context files</li>
<li><code>SKILL.md</code> — the main logic file</li>
</ul>
<p>Now, if you’re using Claude Code, you’d use <code>.claude/skills/weekly-standup/</code>. For GitHub Copilot, it would be <code>.github/skills/weekly-standup/</code>. The structure is the same — only the parent directory changes.</p>
<h2 id="the-fetch-commits-script">The Fetch Commits Script<a aria-hidden="true" tabindex="-1" href="#the-fetch-commits-script"><span class="anchor-link"> #</span></a></h2>
<p>Let’s create the script that will fetch our git commits. This script needs to accept time period arguments so we can ask for “this week” or “last week” or any custom range.</p>
<pre class="astro-code github-dark" style="background-color:#24292e;color:#e1e4e8;overflow-x:auto" tabindex="0" data-language="bash"><code><span class="line"><span style="color:#6A737D">#!/bin/bash</span></span>
<span class="line"><span style="color:#6A737D"># Usage: ./fetch-commits.sh --since=&quot;1 week ago&quot; --until=&quot;today&quot;</span></span>
<span class="line"><span style="color:#B392F0">git</span><span style="color:#9ECBFF"> log</span><span style="color:#79B8FF"> --pretty=format:</span><span style="color:#9ECBFF">&quot;%h|%s|%b&quot;</span><span style="color:#79B8FF"> --no-merges</span><span style="color:#9ECBFF"> &quot;</span><span style="color:#79B8FF">$@</span><span style="color:#9ECBFF">&quot;</span></span></code></pre>
<p>Here’s what this script does. It accepts standard git log arguments — things like <code>--since</code> and <code>--until</code>. The <code>--pretty=format</code> flag lets us structure the output in a way that the AI can easily parse. We’re outputting the commit hash, the subject, and the body, separated by pipes.</p>
<p>The <code>--no-merges</code> flag excludes merge commits, which we typically don’t want in a standup because they’re not actual code changes.</p>
<p>The <code>$@</code> at the end just passes all arguments through to git log, so we can use any valid git date format.</p>
<p>This script is intentionally simple. It outputs structured commit data, and then the AI does the heavy lifting of categorizing and formatting that data.</p>
<h2 id="the-skillmd-logic">The SKILL.md Logic<a aria-hidden="true" tabindex="-1" href="#the-skillmd-logic"><span class="anchor-link"> #</span></a></h2>
<p>Now we create the main skill logic in <code>SKILL.md</code>. This file has two parts: the YAML frontmatter at the top, and the markdown instructions below.</p>
<pre class="astro-code github-dark" style="background-color:#24292e;color:#e1e4e8;overflow-x:auto" tabindex="0" data-language="yaml"><code><span class="line"><span style="color:#85E89D">name</span><span style="color:#E1E4E8">: </span><span style="color:#9ECBFF">weekly-standup</span></span>
<span class="line"><span style="color:#85E89D">allowed-tools</span><span style="color:#E1E4E8">:</span></span>
<span class="line"><span style="color:#E1E4E8">  - </span><span style="color:#9ECBFF">bash</span></span>
<span class="line"><span style="color:#E1E4E8">  - </span><span style="color:#9ECBFF">read</span></span></code></pre>
<p>The YAML frontmatter defines the skill name and which tools are allowed. We’re allowing <code>bash</code> so the skill can run our fetch-commits script, and <code>read</code> so it can read any reference files we provide.</p>
<p>Now for the instructions. We want the skill to:</p>
<ol>
<li>Execute the fetch-commits script with the requested time period</li>
<li>Categorize commits into features, bugs, and refactoring</li>
<li>Format the output as “What I worked on”, “Blockers”, and “Next steps”</li>
</ol>
<p>When we invoke this skill, the AI reads these instructions, runs the script, analyzes the output, and generates our standup. It’s like having a personal assistant who knows exactly what you need.</p>
<h2 id="the-aha-moment">The “Aha!” Moment<a aria-hidden="true" tabindex="-1" href="#the-aha-moment"><span class="anchor-link"> #</span></a></h2>
<p>Now for the fun part. Let’s actually run this and see what we get.</p>
<p>When we invoke the skill with “generate my standup for this week,” the AI:</p>
<ul>
<li>Runs the fetch-commits script</li>
<li>Analyzes the commit messages</li>
<li>Categorizes them appropriately</li>
<li>Generates a formatted standup</li>
</ul>

<h2 id="advanced-features">Advanced Features<a aria-hidden="true" tabindex="-1" href="#advanced-features"><span class="anchor-link"> #</span></a></h2>
<p>Let’s make our standup skill even more powerful with some advanced features.</p>
<p><strong>Enhancement 1: Flexible Time Periods</strong></p>
<p>We can update the skill to accept natural language like “this week”, “last week”, or “since Monday”. The script translates these into git log date arguments.</p>
<p>For example, when you say “generate standup since Monday,” the skill translates that to <code>--since=&quot;last Monday&quot;</code> and passes it to the script.</p>
<p><strong>Enhancement 2: Adding Context from PRs and Issues</strong></p>
<p>We can reference a <code>references/team-projects.md</code> file that maps commit messages to project names. Now the skill can output more meaningful information like “Worked on Auth Service: Fixed login bug, refactored token handling” instead of just raw commit messages.</p>
<p><strong>Enhancement 3: Smart Blocker Detection</strong></p>
<p>We can search commit messages for patterns like “WIP”, “TODO”, or “BLOCKED” and automatically populate a “Blockers” section. For example, if a commit message says “BLOCKED: OAuth integration (see commit abc123)”, the skill catches that and includes it in the blockers section.</p>

<h2 id="best-practices--pitfalls">Best Practices &amp; Pitfalls<a aria-hidden="true" tabindex="-1" href="#best-practices--pitfalls"><span class="anchor-link"> #</span></a></h2>
<p>Here are some things to keep in mind when building your own skills.</p>
<p><strong>Script Arguments</strong>: Design your scripts to accept flexible inputs. Instead of hardcoding dates, accept time periods like “this week” or “last week”. This makes your skill adaptable to different situations.</p>
<p><strong>Tool Availability</strong>: Remember — if your skill uses <code>git</code>, Git must be installed on the host machine. The skill doesn’t install it for you. Same with any other command-line tools. The skill orchestrates what’s already there.</p>
<p><strong>Relative Paths</strong>: Always refer to your reference files using relative paths like <code>./references/template.md</code>. This makes your skill portable across different projects.</p>
<p><strong>One Skill, One Job</strong>: This is probably the most important one. Don’t try to build a “Do Everything” skill. Make a “Standup Generator” skill and a separate “Code Reviewer” skill. Each skill should have a single, clear purpose. This makes them easier to maintain and more reliable.</p>
<h2 id="conclusion">Conclusion<a aria-hidden="true" tabindex="-1" href="#conclusion"><span class="anchor-link"> #</span></a></h2>
<p>Let’s recap what we covered today.</p>
<p>We learned that skills are simply context and instructions packaged together. They’re not installing new software — they’re orchestrating the tools your AI agent already has.</p>
<p>We covered the directory conventions: OpenAI Codex uses <code>.agents/skills/</code>, Claude Code uses <code>.claude/skills/</code>, GitHub Copilot uses <code>.github/skills/</code>.</p>
<p>And we built a working Weekly Standup Generator that analyzes git commits and generates formatted standup updates. We saw how scripts with arguments make skills flexible, and how reference files provide context.</p>
<p>The key takeaway is this: <strong>Skills turn repetitive manual work into one-click automation.</strong> Instead of scrolling through fifty git commits every Monday morning, you invoke your skill and get a formatted standup in seconds.</p>
