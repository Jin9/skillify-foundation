# Skill Bundle Template (Skillify-format SKILL.md)

**Parent:** [`../templates.md`](../templates.md)
**Owner:** Orchestrator (deterministic packager — `package_skill.py`) · **`template_version`:** 0.1.0

The squad's terminal output is a skillify-format skill bundle assembled by the orchestrator's deterministic packager (NOT a sub-agent dispatch — `skillify` is excluded from the per-role skill registry per [`../skills.md`](../skills.md) § "Explicitly excluded skills"; the user's catalog does not contain it). This template defines the file shape the packager emits.

**Triggered at terminal states:** `Done` and `ShipWithCaveats`. NOT emitted on `Failed` or `HardFail`.

**Output root:** `<workflow_root>/SKILL.md` + sibling directories below.

---

## File layout

```
<workflow_root>/
├── SKILL.md                              # the entry point (this template)
├── references/
│   ├── ba-acceptance-criteria.md         # mirrored from .squad-run/ba.json
│   ├── architecture/
│   │   ├── components.json               # mirrored from design/architecture/
│   │   ├── infra-summary.md
│   │   ├── infra-topology.md
│   │   ├── connectivity.md
│   │   ├── observability-spec.md
│   │   └── ADRs/                         # mirrored as a tree
│   ├── requirement/                      # mirrored EPIC + STORY MDs
│   ├── components/                       # one per service: td.json + erd.md
│   └── spec/                             # per-API spec MDs by <service>-<aggregate>
├── templates/                            # the 18 design-doc templates copied verbatim
├── tests/
│   ├── qa-l1-<svc>.json                  # one per component
│   ├── qa-l1-<svc>.csv
│   ├── qa-l2.json
│   └── qa-l2.csv
├── ADVISORY.md                           # always emitted (low-severity findings)
├── PLAN_NOTES.md                         # if any plan-stage advisories
└── KNOWN_ISSUES.md                       # if ShipWithCaveats; lists cap-exceedance caveats
```

## SKILL.md frontmatter (required, in this order)

```markdown
---
name: <slug>                              # from state.json.run_id minus the date suffix
description: <one-line trigger heuristic> # from ba.json.purpose, condensed to ≤120 chars
when_to_use: <bulleted invocation cues>   # derived from BA EPICs (one bullet per EPIC slug)
not_for: <bulleted exclusions>            # derived from ba.json.out_of_scope
domain: <b2c-retail | fintech>            # from state.json.domain
template_version: 0.1.0
generated_at: <ISO-8601 date from state.json.started_at>
generator: package_skill.py@<sha>
source_run_id: <state.json.run_id>
terminal_state: <Done | ShipWithCaveats>
---
```

## SKILL.md body sections (required, in this order)

1. **`# <Workflow Name>`** — H1 from `ba.json.workflow_name`.
2. **`## Inputs`** — bulleted list mirrored from `ba.json.in_scope` (top-level items only; deeper nesting links to `references/ba-acceptance-criteria.md`).
3. **`## Steps`** — ordered list of EPICs in dependency order from `requirement/<EPIC>/<EPIC>.md` frontmatter `dependencies[]`. Each step links to its EPIC MD under `references/requirement/`.
4. **`## Acceptance Criteria`** — single sentence pointing to `references/ba-acceptance-criteria.md`. Don't inline the whole AC list (lives there).
5. **`## Architecture`** — bulleted links to the 6 architecture artifacts under `references/architecture/`: `components.json`, `infra-summary.md`, `infra-topology.md`, `connectivity.md`, `observability-spec.md`, `ADRs/` (linked as a tree).
6. **`## Per-Component Specs`** — one bullet per component name from `state.json.components`, linked to `references/components/<svc>/td.json` + `references/components/<svc>/erd.md`.
7. **`## API Reference`** — link to `references/spec/` index (the packager generates an index MD listing every per-API MD by `<service>-<aggregate>/<API>.md`).
8. **`## Tests`** — link to `tests/qa-l1-*.csv` (per component) and `tests/qa-l2.csv` (system).
9. **`## Known Issues`** — only emitted if `terminal_state == ShipWithCaveats`; one bullet per `KI-N` from `KNOWN_ISSUES.md` with severity prefix and link.
10. **`## Advisories`** — link to `ADVISORY.md`.
11. **`## Provenance`** — fixed text: `"Generated by squad-flow workflow squad. See run-log.md and run-report.md under .squad-run/runs/<run_id>/ for the full execution narrative."`

## Source-of-truth mapping (packager inputs → bundle outputs)

| Squad artifact (input) | Bundle destination (output) |
|---|---|
| `state.json` | SKILL.md frontmatter (name, generated_at, source_run_id, terminal_state) |
| `ba.json` | `references/ba-acceptance-criteria.md` + SKILL.md frontmatter (description, when_to_use, not_for) |
| `requirement/<EPIC>/<EPIC>.md` + `<STORY>.md` | `references/requirement/` (mirror) + SKILL.md `## Steps` (ordered by EPIC dependencies) |
| `design/architecture/contracts.json` + `components.json` + 4 architecture MDs + ADRs | `references/architecture/` (mirror) + SKILL.md `## Architecture` |
| `design/components/<svc>/td.json` + `erd.md` | `references/components/<svc>/` (mirror) + SKILL.md `## Per-Component Specs` |
| `design/spec/<service>-<aggregate>/<API>.md` | `references/spec/<service>-<aggregate>/<API>.md` (mirror) + auto-generated index |
| `docs/templates/*.md` (the 18 squad templates) | `templates/` (verbatim copy — useful when the bundle is consumed by another instance of the squad) |
| `.squad-run/components/<svc>/{qa-l1.csv, qa-l1.json}` | `tests/qa-l1-<svc>.{csv,json}` |
| `.squad-run/layer-2/{qa-l2.csv, qa-l2.json}` | `tests/qa-l2.{csv,json}` |
| `.squad-run/ADVISORY.md` | `ADVISORY.md` (verbatim) |
| `.squad-run/PLAN_NOTES.md` (if exists) | `PLAN_NOTES.md` (verbatim) |
| `.squad-run/KNOWN_ISSUES.md` (if `ShipWithCaveats`) | `KNOWN_ISSUES.md` (verbatim) + SKILL.md `## Known Issues` (per-KI summary) |

The packager NEVER fabricates content; every bundle artifact is either a verbatim copy, a deterministic concatenation, or a structured projection of an existing artifact. If a required input is missing, the packager exits non-zero and the orchestrator records a deviation in `run-report.md`.

## Negative examples

### Negative #1 — Skill bundle emitted on `Failed` terminal state

The packager MUST exit 0 without emitting any bundle file when `state.json.terminal_state == "Failed"` or `"HardFail"`. Emitting a bundle for a `Failed` run pollutes the cache and downstream workflows that consume the bundle as input.

### Negative #2 — `## Known Issues` section emitted on `Done` terminal state

If `terminal_state == "Done"`, no `KNOWN_ISSUES.md` exists, and SKILL.md MUST omit `## Known Issues`. Emitting an empty `## Known Issues` reads like the run had unresolved findings when it did not.

### Negative #3 — Frontmatter `description` longer than 120 chars

Skillify convention treats `description` as a one-line trigger heuristic. The packager truncates `ba.json.purpose` to 120 chars + appends ellipsis if necessary; never inlines a multi-paragraph purpose.
