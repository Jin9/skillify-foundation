## Distillation

Domain-Driven Design (DDD) is a software development approach that puts a rich, expert-validated model of the business domain at the center of the code, structured around explicit boundaries called Bounded Contexts [1][5]. Command Query Responsibility Segregation (CQRS) is a much narrower pattern: it says you can use a different model to update data than the one you use to read it [10][11]. The two are often paired — Microsoft's reference guidance walks through combining DDD aggregates, domain events, command handlers, and read-side projections inside a single microservice [15] — but they are not the same thing and do not require each other.
